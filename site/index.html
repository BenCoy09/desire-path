Agents carry 42 tools into every call. Most tasks need three.

desire-path learns which tools a task actually uses from real agent runs, keeps that knowledge as a graph in HydraDB, and hands the agent only those tools. On our 10 held-out tasks it passed all 10 using about nine times fewer prompt tokens than loading everything.

How it works

  1. Real agent runs on the learning tasks are recorded: which tools were used for which words in the task.
  2. Those links between words and tools, plus tools that tend to follow each other, are stored as a graph in HydraDB.
  3. For a new task, the selector scores tools by the words it recognizes, rarer words counting more, and adds tools that usually follow the top picks.
  4. If none of the words are known, it says so and offers no tools. It does not guess.

This page runs the same selector on an exported snapshot of the graph. It is a snapshot, not a live database query.

What we measured

Real Gemini runs (gemini-3.1-flash-lite) on 10 held-out tasks, one run each. Code checks the answers, files and memory, not an LLM judge.

MethodPassedPrompt tokens per taskLLM calls
Load all 42 tools10/1029,3524.3
BM25 keywords, top 54/1010,8355.9
BM25 keywords, top 32/105,6226.3
desire-path graph, 5 tools10/103,2393.1

Offline check without calling the model: the share of needed tools the selector offered (recall, as defined in scripts/offline_eval.py). Graph: 0.97 at 3 tools, 1.00 at 4 or more. BM25: 0.27 at 3 tools, 0.60 at 8. This check ran on an in-memory copy, not HydraDB.

What this does not show

  • Ten test tasks, one run each. A small sample.
  • The test tasks are new instances of workflows the graph learned from. We have not shown it works on new kinds of work.
  • We compared against loading everything and one-shot keyword search. We have not yet compared against an agent that can search again, or against embeddings.
  • Runs with 300 and 1,000 tools hit API quota errors, so we have no result for them.

Run it yourself

You need HydraDB built from its repository, Node, Python, and a Gemini API key kept out of the repo.

git clone https://github.com/BenCoy09/desire-path cd desire-path && python3 -m venv .venv && source .venv/bin/activate pip install -r requirements.txt
python scripts/ingest_tools.py python scripts/run_agent.py --method preload --split test

The README lists every step, including starting HydraDB.

desire-path was built for the HydraDB hackathon, track 2. It is unrelated to scbrown/desire-path, which tracks failed tool calls.
