Paths before pavement

Park designers know the pattern: people ignore the paved route and wear a dirt track along the shortcut they actually want. These are called desire paths, and some campuses now wait to see where people walk before laying any stone.

Agent tooling is still paved in advance, with every tool listed in every prompt. We do it the other way round. Let the agent walk, record which tools real tasks needed, and make those trails the map.

How it works

1. Learn

Successful runs become edges in HydraDB: task words point to the tools that were needed, and tools point to the ones that usually come next.

2. Traverse

A new task walks those edges in milliseconds. No model call, and only the matching tool definitions go into the prompt.

3. Improve

Every confirmed run strengthens the trail. Teach it in the app and watch the next routing change.

FAQ

What is Desire Path?

A routing layer for AI agents. It learns which tools tasks really use and finds them with a graph walk in HydraDB, so your agent loads a handful of tool definitions instead of all of them.

Does it call an LLM to pick tools?

No. Routing is graph traversal in HydraDB with no model call. The only model calls are in your own agent.

How much does it save?

In real Gemini agent runs on 10 held-out tasks, the graph with 5 tools passed 10 of 10 using 3,241 prompt tokens per task, against 29,352 when loading all 42 tools (also 10 of 10). Keyword search with 5 tools passed 4 of 10. That is a small test, so treat it as early evidence.

Can I try it without signing up?

Yes. Use Try the demo on the sign-in page for a private, temporary workspace. No email needed.

Is my workspace private?

Yes. Lessons you teach inside your workspace only change your own routing. The public app page is a shared demo, so lessons taught there are visible to everyone.

What do you store about me?

Your email, a password hash (never the password itself) and your lessons. We run no analytics. Cookies: one login session cookie, plus your own display settings.

Can I bring my own tools?

Not yet. The demo uses a fixed catalog from four MCP servers. Custom catalogs are the next thing we plan to build.

Is this production ready?

It is an early demo on a free host. The first visit after a quiet spell can take about a minute to wake, and there is no uptime guarantee. Prices shown are proposed.

Can I run it myself?

Yes. The code is open source and uses the open-source HydraDB engine.
